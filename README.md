## 골프 스코어 & 게임 계산기

라운드 중 폰으로 스코어를 입력하면 개인 성적과 여러 내기 게임의 승패·금액이 즉시 계산되고, 마지막에 누가 누구에게 얼마를 보내면 되는지 최소 송금 횟수로 정리해 줍니다. 설치나 서버 없이 브라우저만 있으면 되고, 한 번 열어두면 오프라인에서도 동작합니다. 동반자와 방 코드를 공유하면 각자 자기 폰에서 입력한 점수가 모두에게 실시간으로 반영됩니다.

### 한 번 입력, 모든 게임 자동 계산

개인 스코어만 입력하면 아래 게임이 **모두 항상** 계산됩니다. 설정의 토글은 그 게임의 금액을 정산에 넣을지만 정하고, 리더보드의 각 탭에서도 "정산 포함"을 바로 켜고 끌 수 있습니다.

| 게임 | 방식 | 정산 |
|---|---|---|
| 스트로크 플레이 | 그로스/네트(핸디 적용) 순위 | (선택) 타수 차 × 단가, 전원 1:1 |
| 스테이블포드 | 홀별 점수 합산 (버디 3 · 파 2 · 보기 1 · 이글 4) | 순위만 |
| 스킨스 | 개인 또는 팀(베스트볼), 동타 시 캐리오버 | 스킨당 단가 |
| 매치 플레이 | 개인은 전원 리그전, 팀은 2팀 베스트볼 | 종료 시 홀 차 × 단가 (예: 3&2 → 3홀 차) |
| 나소 | 전반 9 / 후반 9 / 전체 18 세 판의 매치 | 판당 단가 |
| 베스트볼 (팀) | 홀마다 팀원 중 베스트 1개 또는 베스트 2개 합 | 홀 승리당 단가 |
| 라스베가스 (2:2) | 두 명 점수를 낮은수·높은수로 붙여 비교 (4·5 → 45), 상대 버디면 뒤집힘 | 점수 차 × 단가 |
| 보너스 | 니어리스트, 롱기스트, 버디(이글 2배) 횟수는 항상 집계 | 1회당 다른 플레이어 각각 지급 |

- 플레이어 2~8명, 팀은 A~D 4팀까지. 팀을 지정하는 순간 팀 게임이 계산되고, 라운드 중에도 설정에서 바꿀 수 있습니다.
- 핸디캡은 홀별 핸디캡 인덱스에 따라 자동 분배되며 게임마다 네트 적용 여부를 선택할 수 있습니다.
- 9홀/18홀, 홀별 파·핸디캡 인덱스는 입력 중에도 수정 가능합니다.
- 정산 탭에서 개인별 손익, 게임별 내역, 최소 송금 목록을 보여주고 텍스트로 복사/공유할 수 있습니다.
- 데이터는 기기 브라우저(localStorage)에 저장되며, 종료한 라운드는 기록으로 남습니다.

### 상세 기록과 경기 분석

스코어만으로도 분석이 나오고, 상세 기록을 함께 넣으면 더 자세해집니다. 라운드 중간에도, 끝난 뒤 기록에서도 볼 수 있습니다.

- **상세 기록(선택)**: 스코어 입력 화면의 **📝 상세 기록**을 켜면 홀마다 OB·해저드·벙커 횟수, 티샷 방향(좌/페어웨이/우), 퍼트 수를 한두 번의 탭으로 기록합니다. 켜지 않으면 화면은 예전과 같습니다. 기록된 OB·해저드·3퍼트는 모든 사람의 화면에 작은 표시로 보입니다.
- **📊 분석 탭**: 경기 현황(순위·타수 차·최근 3홀 흐름·어려웠던 홀), 플레이어별 요약, 스코어 분포, 누적 스코어 흐름 그래프, 파3/4/5 성적, 전·후반 비교, 상세 기록 집계(벌타 추정, 퍼트, 페어웨이 안착, 파온), 함께 친 사람 비교표를 보여 줍니다.
- **🧢 코치 한마디**: 기록을 규칙으로 해석해 플레이어마다 격려와 팁을 만듭니다. 입력 화면에는 한두 줄, 분석 탭에는 자세히 나오고, **분석 요약 복사 / 공유**로 단톡방에 보낼 수 있습니다. 서버나 AI 호출은 없습니다.
- 인코스(10번홀)부터 시작한 라운드도 "방금 홀·최근 3홀·전반/후반"을 실제 친 순서로 계산합니다.
- 벌타 추정은 OB 2타·해저드 1타로 계산한 참고값이고, 파온은 퍼트를 기록한 홀에서 (타수 − 퍼트 ≤ 파 − 2)로 추정합니다. 스코어가 없는 홀의 상세 기록은 집계하지 않습니다.

### 코스 정보 · 홀 약도 · 공략

- 스코어 입력 화면의 **🗺️ 코스 정보**를 펼쳐 코스 이름과 홀마다 거리(m), 홀 형태(좌 도그렉/직선/우 도그렉), 위험 요소(OB·해저드·벙커의 위치), 공략 메모를 그때그때 입력합니다.
- 입력한 내용으로 홀 약도와 공략 팁이 바로 만들어지고, 오늘의 내 기록(OB 횟수, 티샷이 쏠리는 방향 등)도 반영됩니다. 약도는 입력한 정보로 그린 그림이며 실제 지형이 아닙니다.
- 함께 입력 중이면 동반자 화면에도 실시간으로 공유됩니다.
- **이 코스 저장**을 누르거나 라운드를 종료하면 코스가 기기에 저장되어, 새 라운드에서 같은 코스를 고르면 파·핸디캡·홀 정보가 채워집니다.
- 기본 제공 코스(`courses.js`): 베어크리크 포천의 베어·크리크 코스. 파·핸디캡·화이트티 거리는 공개된 코스 제원표와 스코어카드를 대조한 값이고, "후기 참고" 메모는 공개 라운드 후기를 요약한 비공식 정보입니다. 현장 스코어카드와 다르면 앱에서 고쳐 쓰고 저장하면 내 코스가 우선합니다.

### 동반자와 실시간 공유 (함께 입력)

1. 스코어 입력 화면 오른쪽 위 **👥 함께** → **공유 시작**. 8자리 방 코드(예: `ABCD-EFGH`)와 링크가 만들어집니다.
2. 동반자는 링크를 누르거나, 앱 홈의 **코드로 참여**에 코드를 입력합니다.
3. 이후 누구나 점수를 입력할 수 있고, 모두의 화면에 바로 반영됩니다. "나는 누구?"로 내 줄을 강조할 수 있습니다.
4. **각자 자기 점수만 입력**: 내가 누구인지 고르면 입력 범위를 **내 점수만 / 모두 입력** 중에서 정할 수 있습니다. 참여자는 "내 점수만"이 기본이라 다른 사람 줄은 보기만 되고, 방을 만든 사람은 "모두 입력"이 기본입니다. 폰이 없는 동반자가 있으면 언제든 "모두 입력"으로 바꿔 대신 넣을 수 있습니다. 이 설정은 기기마다 따로이며 실수 방지용입니다(코드를 가진 사람의 입력을 기술적으로 막지는 않습니다).

동작 방식과 한계:

- 서버 없이 **공개 MQTT 중계 서버**(WebSocket)를 통해 전송합니다. 내용은 방 코드에서 유도한 키(PBKDF2 → AES-GCM)로 암호화되지만, 공개 서버를 거치므로 실명·연락처는 쓰지 마세요.
- 방마다 중계 서버 하나를 고정해 사용합니다. 호스트가 공유를 시작할 때 연결되는 서버를 고르고, 참여자는 링크에 담긴 서버 정보(또는 코드로 순차 탐색)로 같은 서버에 붙습니다.
- 늦게 들어온 사람은 서버에 남은 최신 스냅샷을 받고, 스냅샷이 없으면 접속 중인 다른 기기가 응답해 줍니다.
- 연결이 끊겨도 입력은 기기에 저장되고, 다시 연결되면 필드 단위 "최신 변경 우선" 규칙으로 자동 병합됩니다. 같은 칸을 동시에 고치면 나중 입력이 남습니다.
- 호스트가 **라운드 종료**를 누르면 모두에게 종료가 표시되고, 호스트는 **공유 종료**로 서버의 데이터를 지울 수 있습니다(연결된 상태에서만 가능).
- 라운드를 기록으로 저장한 뒤 같은 초대 링크나 코드를 다시 열면 서버를 뒤지지 않고 기록의 그 라운드를 복원해 다시 연결합니다. 라운드를 삭제한 기기도 서버에 남은 스냅샷으로 다시 참여할 수 있습니다.
- 백그라운드/화면 꺼짐 후 돌아오면 연결을 새로 맺어 그 사이 입력을 다시 보냅니다. 다른 기기의 시계가 하루 이상 앞서 있으면 그 입력은 무시됩니다.
- 카카오톡 등 메신저 안의 브라우저에서 열면 홈 화면 앱과 저장소가 분리됩니다. 앱에서 쓰려면 코드를 입력해 참여하세요.
- 고급 설정에서 중계 서버 주소를 직접 지정할 수 있습니다(참여자 모두 같은 주소여야 함).

### 사용 방법

1. `golf-score/index.html`을 브라우저로 열거나, GitHub Pages 주소로 접속합니다. (실시간 공유는 HTTPS 또는 localhost에서만 동작합니다.)
2. 폰에서는 "홈 화면에 추가"를 하면 앱처럼 전체 화면으로 쓸 수 있습니다.
3. 새 라운드 → 플레이어·팀·정산 선택 → 라운드 시작 → 홀마다 스코어 입력 → 리더보드/정산 확인.

로컬에서 띄워 보려면:

```bash
cd golf-score
npm start        # http://localhost:8787
npm test         # 게임 계산 + 분석 + 동기화 로직 단위 테스트 (node --test)
```

실시간 공유 전송 계층 통합 테스트는 MQTT 브로커가 필요합니다. 예를 들어 [aedes](https://github.com/moscajs/aedes)로 `ws://localhost:1884`에 브로커를 띄운 뒤:

```bash
MQTT_URL=ws://localhost:1884/mqtt node --test tests/sync.transport.test.js   # mqtt 패키지가 require 가능해야 함
```

### GitHub Pages 배포

`.github/workflows/pages.yml`이 `main` 브랜치에 푸시될 때 테스트를 돌린 뒤 저장소 전체를 GitHub Pages로 배포합니다.
처음 한 번만 저장소 설정을 아래 순서대로 맞춥니다. (워크플로우의 토큰으로는 Pages를 켤 수 없어 수동 설정이 필요합니다.)

1. **Settings → General → Default branch**를 `main`으로 바꿉니다. Pages를 켤 때 GitHub가 `github-pages` 환경에 "기본 브랜치만 배포 가능" 규칙을 자동으로 붙이므로, 기본 브랜치가 `main`이 아니면 배포가 `Branch "main" is not allowed to deploy to github-pages` 오류로 막힙니다.
2. **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다.
3. **Actions → Deploy to GitHub Pages**에서 실패한 실행을 다시 돌리거나(Re-run), `main`에 푸시합니다.

Pages를 먼저 켰다면 Settings → Environments → github-pages → Deployment branches and tags에 `main`을 추가하면 됩니다.
배포 후 주소는 `https://<계정>.github.io/<저장소>/golf-score/` 입니다.

### 구조

```
golf-score/
├── index.html           # 진입점
├── app.js               # 화면/상태/이벤트 (vanilla JS, 빌드 없음)
├── games.js             # 게임 계산 순수 함수 (브라우저 + Node 공용)
├── analysis.js          # 경기 분석·코치 한마디·홀 공략 순수 함수 (브라우저 + Node 공용)
├── courses.js           # 기본 제공 코스 데이터 (파·핸디캡·거리·메모)
├── sync.js              # 실시간 공유: 키 투영·LWW 병합·암호화·MQTT 세션 (브라우저 + Node 공용)
├── vendor/mqtt.min.js   # mqtt.js 5 (MIT), 공유 시작/참여 시에만 지연 로딩
├── styles.css
├── sw.js                # 오프라인 캐시 서비스 워커
├── manifest.webmanifest
└── tests/
    ├── games.test.js          # 계산 로직
    ├── analysis.test.js       # 분석·코치·홀 공략 로직
    ├── sync.test.js           # 병합/검증/암호화 로직
    └── sync.transport.test.js # 실제 브로커를 통한 통합 테스트 (MQTT_URL 필요)
```
