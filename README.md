## 제이크의 야디지북 (Jake's Yardagebook)

골프 스코어 & 내기 게임 계산기입니다. 시작화면·탭 제목·상단 바에 **제이크의 야디지북**이라는 이름이 나오고, 홈 화면에 추가했을 때 아이콘 밑에는 짧게 "야디지북"으로 나옵니다.

라운드 중 폰으로 스코어를 입력하면 개인 성적과 여러 내기 게임의 승패·금액이 즉시 계산되고, 마지막에 누가 누구에게 얼마를 보내면 되는지 최소 송금 횟수로 정리해 줍니다. 설치나 서버 없이 브라우저만 있으면 되고, 한 번 열어두면 오프라인에서도 동작합니다. 동반자와 방 코드를 공유하면 각자 자기 폰에서 입력한 점수가 모두에게 실시간으로 반영됩니다.

### 한 번 입력, 모든 게임 자동 계산

개인 스코어만 입력하면 아래 게임이 **모두 항상** 계산됩니다. 설정의 토글은 그 게임의 금액을 정산에 넣을지만 정하고, 리더보드의 각 탭에서도 "정산 포함"을 바로 켜고 끌 수 있습니다. 리더보드의 게임 탭마다 맨 위에 그 게임의 룰이 짧게 적혀 있습니다(그 라운드의 금액과 설정에 맞춰 나옵니다).

| 게임 | 방식 | 정산 |
|---|---|---|
| 스트로크 플레이 | 그로스/네트(핸디 적용) 순위. 종합 탭의 '홀별 스코어' 표에 홀마다 플레이어별 타수와 버디 · 파 · 보기 · 더블 등을 표시 | (선택) 타수 차 × 단가, 전원 1:1 |
| 스테이블포드 | 홀별 점수 합산 (버디 3 · 파 2 · 보기 1 · 이글 4) | 순위만 |
| 스킨스 | 개인 또는 팀(베스트볼), 동타 시 캐리오버. 개인전은 공금 방식(시작 지급 · 홀 상금 · OECD 벌금 · 캐디피) 선택 가능 | 공금 방식: 공금 장부로 정리 / 아니면 스킨당 단가 |
| 오장 | 홀마다 타수 차를 둘씩 주고받는 타당 스트로크. 조건에 따라 배판(2배), 파3 니어, 버디값 | 타수 차 × 타당 금액 (기본 5,000원) |
| 매치 플레이 | 개인은 전원 리그전, 팀은 2팀 베스트볼 (홀마다 팀에 적용된 타수와 그 타수를 친 사람을 '홀별 베스트' 표로 보여 줌) | 홀 차 × 단가 (예: 3&2 → 3홀 차). 매치가 진행 중이어도 지금까지의 홀 차로 정산에 들어가고, 끝나면 확정됨. 그래서 매치가 끝나기 전에 라운드를 마치면 그때의 홀 차로 정산됨. 매치와 나소는 친 순서로 겨루고(10번홀 출발이면 18번홀 다음이 1번홀), 앞선 홀 수가 아직 치지 않은 홀 수보다 많아지면 끝남 (빌드 16부터 만든 라운드. 그 전에 만든 라운드와 기록은 홀 번호 순 그대로) |
| 나소 | 전반 9 / 후반 9 / 전체 18 세 판의 매치 (팀전은 매치 플레이처럼 '홀별 베스트' 표를 보여 줌) | 판당 단가 |
| 베스트볼 (팀) | 홀마다 팀원 중 베스트 1개 또는 베스트 2개 합 | 홀 승리당 단가 |
| 라스베가스 (2:2) | 두 명 점수를 낮은수·높은수로 붙여 비교 (4·5 → 45), 상대 버디면 뒤집힘 | 점수 차 × 단가 |
| 보너스 | 니어리스트, 롱기스트, 버디(이글 2배) 횟수는 항상 집계 | 1회당 다른 플레이어 각각 지급 |

- 플레이어 2~8명, 팀은 A~D 4팀까지. 팀을 지정하는 순간 팀 게임이 계산되고, 라운드 중에도 설정에서 바꿀 수 있습니다.
- 핸디캡은 홀별 핸디캡 인덱스에 따라 자동 분배되며 게임마다 네트 적용 여부를 선택할 수 있습니다.
- 9홀/18홀, 홀별 파·핸디캡 인덱스는 입력 중에도 수정 가능합니다.
- **양파 한도**(선택, 스트로크 플레이 설정): 켜면 한 홀 타수를 파의 두 배(파3 6타 · 파4 8타 · 파5 10타)까지만 셉니다. 입력도 그 타수에서 멈추고, 그보다 크게 적혀 있던 타수도 한도로 계산합니다(저장된 값은 그대로). 모든 순위·게임·분석에 똑같이 적용됩니다.
- **내기 시작 홀**(선택, 새 라운드 · 라운드 설정): 몸이 풀린 뒤부터 내기를 할 때 "N번째 홀부터"를 고릅니다(처음부터 · 4번째 홀부터 · 후반부터, 또는 직접). 그 앞에 친 홀은 순위 · 스테이블포드 · 기록에만 들어가고, 돈이 걸린 게임(스트로크 내기 · 스킨스 · 오장 · 매치 · 나소 · 베스트볼 · 라스베가스 · 보너스)에서는 모두 빠집니다. 매치와 나소는 남은 홀만으로 겨루고(나소에서 한 홀도 남지 않은 판은 겨루지 않음), 스킨스 이월과 오장의 "앞 홀 전원 동타" 배판은 내기를 시작한 홀부터 새로 셉니다. 순서는 친 순서를 따릅니다(10번홀 출발이면 10번홀이 첫 번째). 리더보드에서 돈이 걸린 탭마다 어느 홀부터인지 안내가 나옵니다(스테이블포드와, 타당 금액이 없는 종합에는 나오지 않음)
- **오장**: 홀마다 타수 차 × 타당 금액을 서로 주고받습니다(이름은 기본 금액 5천 원에서 왔고 금액은 바꿀 수 있습니다). 버디 이하 · 트리플 보기 이상 · 파3에서 더블 보기 이상 · 3명 이상 동타가 나온 홀은 배판(2배)이고, 전원이 동타면 다음 홀이 배판입니다(끌 수 있음). 조건이 여러 개 겹쳐도 2배입니다. 파3에서 니어리스트로 고른 사람이 파 이하로 마치면 다른 사람 각각에게서 1타 금액을 더 받고(파를 못 하면 없던 것으로), 버디 이하를 하면 버디값으로 1타 금액을 더 받습니다. 니어와 버디값도 배판 홀에서는 2배이며 각각 끌 수 있습니다. 타수 차는 네트를 켜면 핸디 적용 타수로 계산하고, 배판 조건은 실제 타수로 봅니다. 전원이 타수를 넣은 홀만 계산합니다.
- **스킨스 공금 방식**(선택, 개인전. 새 라운드는 켠 채로 시작): 각자 같은 돈(기본 10만 원)을 내서 공금을 만들고, 시작할 때 플레이어 각각과 캐디에게 정한 돈(기본 1만 원씩)을 줍니다. 홀마다 단독 승자가 홀당 상금(기본 2만 원 × 이월된 스킨 수)을 공금에서 받습니다. 끝나면 남은 공금으로 캐디피(기본 15만 원)를 내고, 남으면 똑같이 돌려받고 모자라면 똑같이 나눠 냅니다(나누어떨어지지 않으면 원 단위로 나눠 합계가 정확히 맞게 합니다). 리더보드 스킨스 탭의 표에는 사람별 스킨 수와 받은 돈(시작 지급 + 상금 − 벌금)이 나오고, **공금 장부**에 공금이 얼마였고 누가(플레이어 · 캐디) 얼마를 가져갔는지, 얼마가 남거나 모자라는지 나오며(낸 돈까지 넣은 손익은 정산 탭에 있습니다), 정산 탭의 송금 정리에는 캐디에게 줄 돈이 "→ 캐디" 줄로 들어갑니다. 홀마다 돈을 나눠 주지 않아도 끝에 한 번에 정리할 수 있고, 장부는 라운드 기록과 결과 복사 글에 함께 남습니다. 공금을 실제로 **미리 걷었으면**(새 라운드의 기본값. 시작 지급도 이미 준 것으로 봅니다) 장부의 "끝나고 나눌 돈"에 걷어 둔 돈으로 누구에게 얼마를 주고 누가 얼마를 더 내는지가 나오고, 정산 탭과 결과 복사 글의 "스킨스 공금" 줄도 언제나 이와 같습니다(캐디피는 공금에서 나갑니다). 오장 같은 다른 게임을 함께 하면 그 돈은 공금과 섞지 않고 플레이어끼리 주고받는 줄로 따로 정리합니다. **걷지 않았으면** 모든 게임을 합쳐 누가 누구에게(캐디 포함) 얼마를 보낼지로 나옵니다. 어느 쪽이든 손익은 같고, 장부에서 바로 바꿀 수 있습니다(끝난 기록에서도). 걷은 돈(각자 내는 돈 × 인원)이 시작할 때 나눠 준 돈(플레이어와 캐디 몫의 합)보다 많지 않으면 걷어 둘 돈이 없으므로 걷지 않은 것으로 계산합니다. 금액은 모두 바꿀 수 있고 0으로 두면 그 항목은 없는 것으로 봅니다. 공금 방식을 끄면 예전처럼 스킨 하나에 다른 사람 각각이 스킨당 금액을 줍니다. 팀 스킨스는 언제나 스킨당 금액으로 계산합니다. 업데이트 전에 만든 라운드는 예전 방식 그대로(스킨당 금액, 이월은 홀 번호 순) 계산해 이미 정산한 금액이 바뀌지 않고, 업데이트 뒤 처음 만드는 새 라운드부터 공금 방식이 켜진 채로 시작합니다. 스킨스를 "정산 제외"로 두면 장부는 참고용으로만 보이고 정산 탭과 결과 복사 글에는 들어가지 않습니다.
- **OECD 룰**(선택, 공금 방식에서): 상금으로 받은 돈(낸 벌금은 뺌)이 **가입 기준**(기본 6만 원. 홀당 상금 2만 원이면 스킨 3개) 이상이 된 사람은 그다음 홀부터 OB · 벙커 · 해저드 · 3퍼트 · 트리플 이상을 하면 걸린 항목마다 벌금(기본 1만 원)을 공금에 넣습니다. 시작 지급은 가입 기준에 넣지 않습니다. 벌금은 가진 돈까지만 내고, 벌금을 내서 가입 기준 아래로 내려가면 다시 채울 때까지 대상에서 빠집니다. 가입 기준은 설정에서 바꿀 수 있고, 0으로 두면 본전 기준(공금에서 받은 돈이 낸 돈 이상일 때 가입)입니다. 가입 기준이 생기기 전에 만든 라운드는 본전 기준 그대로 계산해 이미 낸 벌금이 바뀌지 않습니다. OB · 벙커 · 해저드 · 퍼트 수는 📝 상세 기록에 입력한 값으로, 트리플 이상은 타수로 판정합니다. 홀 순서는 실제로 친 순서(10번홀 출발이면 10번홀부터, 18번홀의 이월은 1번홀로)를 따르고, 어느 홀에서 출발한 것으로 계산했는지 스킨스 탭과 오장 탭에 적혀 있습니다. 오장과는 별개의 게임입니다.
- **니어 · 롱기 룰**(게임 설정의 보너스 카드. 새 라운드는 셋 다 켠 채로 시작): **니어는 파3 홀에서만**, **롱기는 파5 홀에서만** 고를 수 있게 하면 스코어 입력 화면에 그 홀에서만 고르는 줄이 나오고, 다른 홀에 남아 있는 표시는 횟수에도 돈에도 넣지 않습니다. **지우개**는 파3에서 그린에 올리지 못한 사람이 파 이하로 마치면 그 홀의 니어를 지우는 룰입니다. 니어를 고르면 그 아래에 지운 사람을 고르는 줄이 나오고, 지운 사람의 타수가 파 이하로 입력돼 있을 때만 인정합니다(파를 못 했으면 니어는 그대로). 지워진 니어는 횟수에도 보너스 정산에도 넣지 않으며 오장의 니어값도 없던 것으로 합니다. 누가 누구의 니어를 지웠는지는 보너스 탭에 남습니다. 세부 조건(웨지로 쳤는지, 니어가 버디일 때 등)은 모임마다 달라서 앱은 따지지 않고, 지웠다고 고른 것을 따릅니다. 이 설정들이 생기기 전에 만든 라운드는 예전처럼 어느 홀에서든 고른 대로 세고, 업데이트 뒤 처음 만드는 새 라운드부터 켜진 채로 시작합니다.
- 정산 탭에서 개인별 손익, 게임별 내역, 최소 송금 목록을 보여주고 텍스트로 복사/공유할 수 있습니다.
- 데이터는 기기 브라우저(localStorage)에 저장되며, 종료한 라운드는 기록으로 남습니다.

### 상세 기록과 경기 분석

스코어만으로도 분석이 나오고, 상세 기록을 함께 넣으면 더 자세해집니다. 라운드 중간에도, 끝난 뒤 기록에서도 볼 수 있습니다.

- **상세 기록(선택)**: 스코어 입력 화면의 **📝 상세 기록**을 켜면 홀마다 OB·해저드·벙커 횟수, 티샷 방향(좌/페어웨이/우), 퍼트 수를 한두 번의 탭으로 기록합니다. 켜지 않으면 화면은 예전과 같습니다. 기록된 OB·해저드·3퍼트는 모든 사람의 화면에 작은 표시로 보입니다.
- **타수 자동 계산**: 상세 기록에서 **샷 수**(티샷부터 그린에 올릴 때까지 친 횟수, 퍼트 제외)와 **퍼트 수**를 넣으면 타수가 `샷 + 벌타 + 퍼트`로 계산됩니다. 벌타는 OB 1번에 2타(OB티에서 이어 치는 기준), 해저드 1번에 1타입니다. 계산 중인 칸에서 큰 ＋/−를 누르면 샷 수가 바뀌어 합계와 항상 맞습니다. 샷 수나 퍼트 수를 넣지 않은 칸은 예전처럼 타수를 직접 입력합니다.
- **📊 분석 탭**: 경기 현황(순위·타수 차·최근 3홀 흐름·어려웠던 홀), 플레이어별 요약, 스코어 분포, 누적 스코어 흐름 그래프, 파3/4/5 성적, 전·후반 비교, 상세 기록 집계(벌타 추정, 퍼트, 페어웨이 안착, 파온), 함께 친 사람 비교표를 보여 줍니다.
- **🧢 코치 한마디**: 기록을 규칙으로 해석해 플레이어마다 격려와 팁을 만듭니다. 입력 화면에는 한두 줄, 분석 탭에는 자세히 나오고, **분석 요약 복사 / 공유**로 단톡방에 보낼 수 있습니다. 서버나 AI 호출은 없습니다.
- 인코스(10번홀)부터 시작한 라운드도 "방금 홀·최근 3홀·전반/후반"을 실제 친 순서로 계산합니다. 출발 홀은 입력 순서로 추정하며, 지난 홀을 나중에 몰아서 입력해 틀리게 잡히면 분석 탭의 **출발 홀**에서 1번홀/10번홀을 직접 고를 수 있습니다. 스킨스 이월과 오장의 "앞 홀"도 이 순서를 따르므로, 진행 중인 라운드에서 고른 출발 홀은 함께 보는 기기에도 전해집니다. 호스트가 라운드를 끝낸 뒤에도 그 라운드를 아직 열어 둔 기기끼리는 전해지고, 기록으로 저장된 라운드에서 고치면 그 기기의 기록만 바뀝니다.
- 코치의 순위 이야기("단독 선두", "선두와 N타 차")는 모두가 입력한 홀까지만 비교합니다. 각자 입력하다 보면 한 사람이 한 홀 먼저 넣는 순간이 생기는데, 그때 순위가 뒤집혀 보이지 않게 하기 위해서입니다. 누군가의 입력이 두 홀 이상 밀려 있으면 순위는 말하지 않습니다.
- 종료를 누르지 않고 기록으로 넘어간 라운드도 기록에서 볼 때는 끝난 라운드로 분석합니다.
- 벌타 추정은 OB 2타·해저드 1타로 계산한 참고값이고, 파온은 퍼트를 기록한 홀에서 (타수 − 퍼트 ≤ 파 − 2)로 추정합니다. 스코어가 없는 홀의 상세 기록은 집계하지 않습니다.

### 코스 정보 · 홀 약도 · 공략

- 스코어 입력 화면의 **🗺️ 코스 정보** 카드를 펼쳐 홀마다 거리(m), 홀 형태(좌 도그렉/직선/우 도그렉), 위험 요소, 공략 키워드를 그때그때 입력합니다. 코스 이름은 모든 홀에 공통이라 **⚙ 라운드 설정**에서 고칩니다.
- **코스 안내도 약도가 있는 홀(크리크 코스)은 카드가 보기 전용**입니다. 약도·키워드·공략 설명에 필요한 내용이 이미 나와 있어서 같은 내용을 다시 늘어놓는 입력란을 두지 않습니다. 파·핸디캡은 홀 머리말에서 언제나 고칠 수 있습니다. 코스를 불러오지 않고 라운드 설정에서 코스 이름만 크리크로 적은 라운드에도 그 코스의 거리·위험 요소·키워드가 보입니다. 카드 안에서는 약도의 고저차 설명과 겹치는 `내리막` 같은 키워드를 다시 적지 않습니다(요약 줄에는 나옵니다).
- 위험 요소는 종류(OB·해저드·벙커)마다 한 줄로, 위치(좌·우·그린 앞/주변)를 눌러 표시합니다. 요약 줄에는 `벙커 좌우·그린 주변`처럼 종류별로 묶여 나옵니다.
- 공략 키워드는 `좌우 OB`, `핀보다 짧게`처럼 짧은 말을 하나씩 추가하고 ✕로 지웁니다. 쉼표로 나눠 여러 개를 한 번에 넣을 수 있고, 키워드 하나는 24자까지입니다(넘으면 잘라 넣지 않고 알려 줍니다). 추가를 누르지 않고 다른 홀이나 다른 화면으로 넘어가면 쓰던 글이 그 홀의 키워드로 들어갑니다(이때는 24자를 넘는 글도 버리지 않고 그대로 넣습니다). 쓰던 글은 치는 대로 기기에 적어 두므로 전화가 잠기거나 앱이 다시 열려도 남습니다. 저장과 공유는 예전 메모와 같은 한 칸(최대 200자)이며 키워드 사이를 ` · `로 잇습니다(그 길이로 200자를 넘으면 `·`만으로 잇습니다). 예전에 문장으로 적어 둔 메모는 쉼표·마침표 단위의 토막으로 보입니다.
- 홀 번호 아래 요약(첫 줄은 거리·형태·위험 요소, 그 아래 두 줄까지 공략 키워드. 첫 줄이 길어 한 줄에 안 들어가는 홀은 자르지 않고 키워드와 이어서 세 줄까지)은 항상 같은 높이로 보이고, 누르면 약도와 공략 전체가 있는 코스 정보 카드로 이동합니다. 코스 정보 카드는 점수 칸 아래에 있습니다. 동반자가 정보를 넣거나 팁이 바뀌어 카드 높이가 변해도 점수 버튼이 손가락 밑에서 밀리지 않게 하기 위해서입니다.
- 입력한 내용으로 홀 약도와 공략 팁이 바로 만들어지고, 오늘의 내 기록(OB 횟수, 티샷이 쏠리는 방향 등)도 반영됩니다. 약도는 입력한 정보로 그린 그림이며 실제 지형이 아닙니다.
- 함께 입력 중이면 동반자 화면에도 실시간으로 공유됩니다. 위험 요소는 항목마다 따로 합쳐지므로 두 사람이 같은 홀에 서로 다른 위험 요소를 표시해도 둘 다 남습니다.
- **골프장 받기 · 코스 보내기**(홈 화면, 새 라운드 화면의 "다른 골프장 받기"): 새 골프장을 앱에 넣는 길입니다.
  - **목록에서 받기**: 앱과 함께 올라가 있는 코스 폴더(`golf-score/courses`)의 골프장이 목록으로 나오고, 누르면 폰에 저장됩니다. 받은 골프장은 기본 제공 코스와 똑같이 새 라운드의 "코스 불러오기"에 나오며(라운드의 홀 수와 같은 코스가 나옵니다. 홀 수가 달라 안 보이는 받은 코스가 있으면 그 자리에서 알려 줍니다), 약도가 들어 있으면 홀 약도가 나옵니다. 폴더의 자료가 새로워지면(날짜가 더 늦거나, 같은 날이라도 내용이 달라지면) 목록에 "새로 받기"가 뜹니다.
  - **파일로 받기 · 보내기**: 이 폰에 있는 코스(직접 입력해 저장한 코스 포함)를 "보내기"로 코스 파일(.json)로 만들어 메신저 등으로 보내고, 받은 사람은 "코스 파일 열기"로 받습니다. 한 사람이 입력한 골프장을 여럿이 나눠 쓸 수 있습니다.
  - **목록에 골프장 추가하기(배포자)**: 코스 파일을 코스 폴더에 넣으면 됩니다. 목록 파일은 배포할 때 자동으로 만들어집니다. 자세한 방법은 [`golf-score/courses/README.md`](golf-score/courses/README.md).
  - 함께 입력하는 라운드의 코스가 내 폰에 없고 목록에 약도가 있는 골프장이면, 참여할 때 자동으로 받아 호스트와 같은 약도가 나옵니다.
  - 받은 파일은 남이 만든 것이므로 모두 검증한 뒤에만 받습니다(약도에는 숫자만 허용). 받은 코스는 앱 상태와 따로 기기에 저장됩니다(`golfscore.lib.v1`).
  - 코스 폴더의 목록과 코스 파일은 늘 네트워크에서 받습니다(오프라인용으로 저장해 두지 않습니다). 연결이 안 될 때 예전 사본을 지금 자료로 잘못 아는 일을 막기 위해서이며, 받아 둔 코스는 기기에 있으므로 오프라인에서도 그대로 쓸 수 있습니다. 목록에서 받은 파일이 목록에 적힌 내용과 다르면(아직 예전 파일이 오는 경우) 받았다고 적지 않고 다시 받으라고 알려 줍니다.
  - 받은 코스는 40개까지, 그리고 점수를 저장할 자리가 남는 만큼만 받습니다. 가득 차면 오래된 코스를 말없이 지우지 않고, 안 쓰는 코스를 지우라고 알려 줍니다. 진행 중인 라운드가 쓰는 코스는 지울 수 없습니다.
  - 앱에 들어 있는 코스와 같은 코스를 받아 두었더라도, 앱이 더 새 자료와 함께 갱신되면 예전에 받은 것은 쓰지 않습니다.
- 코스 저장: 라운드가 기록으로 넘어갈 때 코스가 기기에 저장되어, 새 라운드에서 같은 코스를 고르면 파·핸디캡·홀 정보가 채워집니다. 이미 저장해 둔 코스에는 **그 라운드에서 실제로 고친 칸만** 반영하므로, 코스를 불러오지 않고 이름만 적은 라운드나 남이 만든 라운드에 참여한 경우에도 저장해 둔 내용이 지워지지 않습니다. 코스 이름이 없는 라운드는 저장되지 않습니다.
- 기본 제공 코스를 고쳐 쓰면 내 사본이 저장되어 그 값이 우선합니다. 사본은 그때의 기본 제공 값에 라운드에서 고친 칸만 얹어 만들므로, 앱이 갱신되기 전에 시작한 라운드를 넘겨도 옛 자료가 바로잡힌 기본 제공 코스를 가리지 않습니다. 보기 전용 홀의 홀 정보는 이 기기에서 고칠 수 없으므로 사본에 반영하지 않습니다(예전 버전을 쓰는 동반자가 그 홀을 건드려도 내 코스는 그대로입니다). 새 라운드 화면에서 그 코스를 고른 뒤 **기본 제공 값으로 되돌리기**를 누르면 사본을 지우고 원래 값으로 돌아갑니다. 고치지 않은 라운드는 사본을 만들지 않습니다.
- 기본 제공 코스(`courses.js`): 베어크리크 포천의 베어·크리크 코스. 파·핸디캡·화이트티 거리는 공개된 코스 제원표와 스코어카드를 대조한 값이고, 공략 키워드는 공개 라운드 후기를 짧게 간추린 비공식 정보입니다. 크리크 코스의 OB 위치도 안내도에는 없어서 후기에 나온 쪽을 위험 요소(OB 좌/우)로 표시했고, 그래서 공략 팁이 OB 쪽을 피하도록 안내합니다. 위험 요소로 표시한 내용은 키워드에 다시 넣지 않습니다. 예전 버전의 문장형 메모("후기 참고: …")가 그대로 남은 라운드나 저장 코스는 읽을 때 그 홀의 지금 키워드로 바꾸고, 그 문장이 말하던 OB 쪽도 위험 요소로 함께 읽습니다. 그래서 예전 자료로 만든 라운드도 지금 자료와 똑같이 보이고, 저장된 값은 건드리지 않습니다.
- **크리크 코스 홀 약도**(`coursemaps.js`): 골프장 코스 안내도(2023-07-20 기준)를 보고 홀의 생김새(외곽·페어웨이·그린·벙커·물·숲, 티 위치)를 단순하게 옮긴 그림입니다. 코스 정보 카드의 약도를 누르면 크게 보이고, 그린 중심까지 50m 단위 점선, 티별 거리, 화이트티 기준 캐리 거리, 티 대비 고저차가 함께 나옵니다. 정밀한 측량 자료가 아니라 홀의 특징을 보는 용도이며, 약도가 없는 코스는 입력한 정보로 그린 도식이 나옵니다. 약도가 있는 홀의 홀 형태(좌 도그렉/직선/우 도그렉)는 약도 기준이고, 요약 줄과 공략 팁도 그 형태를 따릅니다.

### 동반자와 실시간 공유 (함께 입력)

1. 스코어 입력 화면 오른쪽 위 **👥 함께** → **공유 시작**. 8자리 방 코드(예: `ABCD-EFGH`)와 링크가 만들어집니다.
2. 동반자는 링크를 누르거나, 앱 홈의 **코드로 참여**에 코드를 입력합니다.
3. 이후 누구나 점수를 입력할 수 있고, 모두의 화면에 바로 반영됩니다. "나는 누구?"로 내 줄을 강조할 수 있습니다.
4. **각자 자기 점수만 입력**: 내가 누구인지 고르면 입력 범위를 **내 점수만 / 모두 입력** 중에서 정할 수 있습니다. 참여자는 "내 점수만"이 기본이라 다른 사람 줄은 보기만 되고, 방을 만든 사람은 "모두 입력"이 기본입니다. 폰이 없는 동반자가 있으면 언제든 "모두 입력"으로 바꿔 대신 넣을 수 있습니다. 이 설정은 기기마다 따로이며 실수 방지용입니다(코드를 가진 사람의 입력을 기술적으로 막지는 않습니다).

동작 방식과 한계:

- 서버 없이 **공개 MQTT 중계 서버**(WebSocket)를 통해 전송합니다. 내용은 방 코드에서 유도한 키(PBKDF2 → AES-GCM)로 암호화되지만, 공개 서버를 거치므로 실명·연락처는 쓰지 마세요.
- 방마다 중계 서버 하나를 고정해 사용합니다. 호스트가 공유를 시작할 때 연결되는 서버를 고르고, 참여자는 링크에 담긴 서버 정보(또는 코드로 순차 탐색)로 같은 서버에 붙습니다.
- 늦게 들어온 사람은 서버에 남은 최신 스냅샷을 받고, 스냅샷이 없으면 접속 중인 다른 기기가 응답해 줍니다.
- 연결이 끊겨도 입력은 기기에 저장되고, 다시 연결되면 필드 단위 "최신 변경 우선" 규칙으로 자동 병합됩니다. 같은 칸을 동시에 고치면 나중 입력이 남습니다.
- 호스트가 **라운드 종료**를 누르면 모두에게 종료가 표시되고, 호스트는 **공유 종료**로 서버의 데이터를 지울 수 있습니다(연결된 상태에서만 가능).
- 라운드를 기록으로 저장한 뒤 같은 초대 링크나 코드를 다시 열면 서버를 뒤지지 않고 기록의 그 라운드를 복원해 다시 연결합니다. 라운드를 삭제한 기기도 서버에 남은 스냅샷으로 다시 참여할 수 있습니다.
- 백그라운드/화면 꺼짐 후 돌아오면 연결을 새로 맺어 그 사이 입력을 다시 보냅니다. 다른 기기의 시계가 하루 이상 앞서 있으면 그 입력은 무시됩니다.
- 카카오톡 등 메신저 안의 브라우저에서 열면 홈 화면 앱과 저장소가 분리됩니다. 앱에서 쓰려면 코드를 입력해 참여하세요.
- 고급 설정에서 중계 서버 주소를 직접 지정할 수 있습니다(참여자 모두 같은 주소여야 함).

### 사용 방법

1. `golf-score/index.html`을 브라우저로 열거나, GitHub Pages 주소로 접속합니다. (실시간 공유는 HTTPS 또는 localhost에서만 동작합니다.)
2. 폰에서는 "홈 화면에 추가"를 하면 앱처럼 전체 화면으로 쓸 수 있습니다.
3. 새 라운드 → 플레이어·팀·정산 선택 → 라운드 시작 → 홀마다 스코어 입력 → 리더보드/정산 확인.

로컬에서 띄워 보려면:

```bash
cd golf-score
npm start        # http://localhost:8787
npm test         # 게임 계산 + 분석 + 동기화 로직 단위 테스트 (node --test)
```

실시간 공유 전송 계층 통합 테스트는 MQTT 브로커가 필요합니다. 예를 들어 [aedes](https://github.com/moscajs/aedes)로 `ws://localhost:1884`에 브로커를 띄운 뒤:

```bash
MQTT_URL=ws://localhost:1884/mqtt node --test tests/sync.transport.test.js   # mqtt 패키지가 require 가능해야 함
```

### GitHub Pages 배포

`.github/workflows/pages.yml`이 `main` 브랜치에 푸시될 때 테스트를 돌린 뒤 저장소 전체를 GitHub Pages로 배포합니다.
처음 한 번만 저장소 설정을 아래 순서대로 맞춥니다. (워크플로우의 토큰으로는 Pages를 켤 수 없어 수동 설정이 필요합니다.)

1. **Settings → General → Default branch**를 `main`으로 바꿉니다. Pages를 켤 때 GitHub가 `github-pages` 환경에 "기본 브랜치만 배포 가능" 규칙을 자동으로 붙이므로, 기본 브랜치가 `main`이 아니면 배포가 `Branch "main" is not allowed to deploy to github-pages` 오류로 막힙니다.
2. **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다.
3. **Actions → Deploy to GitHub Pages**에서 실패한 실행을 다시 돌리거나(Re-run), `main`에 푸시합니다.

Pages를 먼저 켰다면 Settings → Environments → github-pages → Deployment branches and tags에 `main`을 추가하면 됩니다.
배포 후 주소는 `https://<계정>.github.io/<저장소>/golf-score/` 입니다.

├── sync.js              # 실시간 공유: 키 투영·LWW 병합·암호화·MQTT 세션, 코스 파일 읽기(검증)·만들기 (브라우저 + Node 공용)

└── tests/
    ├── games.test.js          # 계산 로직
    ├── analysis.test.js       # 분석·코치·홀 공략 로직

    ├── coursefile.test.js     # 코스 파일 읽기(검증)·만들기, 기본 제공 코스 꺼내기, 목록 만들기
    ├── sync.test.js           # 병합/검증/암호화 로직
    └── sync.transport.test.js # 실제 브로커를 통한 통합 테스트 (MQTT_URL 필요)
